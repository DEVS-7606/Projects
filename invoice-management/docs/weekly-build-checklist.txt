WEEKLY BUILD CHECKLIST
PROJECT: Invoice Management MVP
TIMELINE: 6 TO 8 WEEKS
FOCUS: V1 ONLY

==================================================
PROJECT GOAL
==================================================

Build a focused invoice workflow tool for micro-SMEs.

Core user promise:
- User signs up
- User gets a unique forwarding email
- User forwards supplier invoice emails
- System stores file and extracts invoice data
- User reviews invoice in dashboard
- User marks invoice paid when needed

This is NOT:
- accounting software
- ERP
- GST filing software
- WhatsApp automation app
- full finance platform

==================================================
WEEK 0 - PREP AND CLARITY
==================================================

Goal:
Lock project scope before coding.

Tasks:
- Finalize v1 features only
- Create docs folder
- Save all project brief text files
- Create project board with:
  - Todo
  - In Progress
  - Done
  - Bugs
  - Beta Feedback
- Decide stack:
  - React
  - Supabase
  - Tailwind or component library
  - OCR provider
  - email ingestion provider
- Create a rough sitemap
- Define success metric for v1:
  - forward one invoice successfully
  - show it in dashboard
  - user can edit and mark paid

Deliverables:
- Project brief finalized
- Scope freeze for v1
- Task board created

Exit criteria:
- I know exactly what I am building
- I am not adding random features

==================================================
WEEK 2 - DATABASE + PROFILE FLOW
==================================================

Goal:
Create backend structure for profiles, vendors, and invoices.

Tasks:
- Create profiles table
- Create vendors table
- Create invoices table
- Add indexes
- Add constraints
- Add duplicate columns:
  - duplicate_status
  - duplicate_of_invoice_id
- Enable RLS on all tables
- Create policies for user-specific access
- Add updated_at trigger
- Create profile creation flow after signup
- Show profile data in UI
- Show forwarding email card in dashboard:
  invoices+username@yourapp.com

Deliverables:
- Database schema ready
- User profile is created
- Forwarding email shown in UI

Exit criteria:
- Data model is stable enough for CRUD
- User sees their identity and routing email

==================================================
WEEK 3 - VENDOR CRUD
==================================================

Goal:
User can manage vendors.

Tasks:

- Build add vendor form
- Build edit vendor form

- Add search by vendor name

==================================================
WEEK 5 - EMAIL INGESTION + FILE STORAGE
==================================================

Goal:
User can forward invoice emails and create invoice entries from them.

Tasks:
- Set up inbound email routing
- Configure email webhook endpoint
- Parse recipient email to identify username
- Match username to profile
- Extract attachments from incoming email
- Upload invoice file to storage
- Save file_url on invoice record
- Create placeholder invoice entry from forwarded email
- Handle cases:
  - no attachment
  - invalid recipient
  - unknown user
  - multiple attachments
- Add processing feedback in UI if needed

Deliverables:
- Forwarded email creates invoice record
- File is stored successfully

Exit criteria:
- Email-to-invoice pipeline works even without OCR perfection

==================================================
WEEK 6 - OCR + REVIEW FLOW
==================================================

Goal:
Auto-extract invoice fields and let user review them.

Tasks:
- Integrate OCR/document extraction service
- Extract:
  - invoice number
  - vendor name
  - invoice date
  - due date
  - subtotal
  - tax total
  - total amount
  - tax components if available
- Save raw OCR text
- Save extracted fields JSON
- Create review state:
  - mark uncertain invoices as needs_review
- Build invoice review UI:
  - PDF preview
  - extracted fields form
  - confidence correction flow
- Auto-create or match vendor where possible

Deliverables:
- OCR populates invoices
- User can review and correct extracted data

Exit criteria:
- Forwarding one real invoice gives a usable record in dashboard

==================================================
WEEK 7 - DUPLICATES + PAYMENT STATUS + POLISH
==================================================

Goal:
Improve trust and usability.

Tasks:
- Add duplicate detection rules:
  - same vendor + invoice number
  - same vendor + amount + date
  - same invoice number + amount
- Mark duplicate_status as:
  - none
  - suspected
  - confirmed
  - ignored
- Link duplicate_of_invoice_id
- Build duplicate warning UI
- Add mark-as-paid action
- Add payment_reference field handling
- Auto-calculate overdue state from due_date where possible
- Improve validation and form errors
- Improve loading and empty states

Deliverables:
- Duplicate review works
- Mark as paid works
- App feels safer and clearer

Exit criteria:
- User can trust invoice state and review suspicious cases

==================================================

V1 is done when:
- user can sign up and log in

- attachment is stored
- OCR extracts invoice data
- invoice appears in dashboard
- user can edit invoice
- user can manage vendors
- user can mark invoice paid
- user can review duplicates
- app works for beta users
