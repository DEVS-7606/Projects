FRONTEND UI DESIGN BRIEF
PROJECT: Invoice Management MVP
STACK: React
GOAL: Design the full frontend UI for v1 only

1. PRODUCT CONTEXT

This product helps small businesses manage supplier invoices in one place.
Users forward invoice emails to the system.
The system extracts invoice details and displays them in a dashboard.

This is not accounting software.
This is not an ERP.
This is a focused invoice workflow tool.

2. PRIMARY USER JOURNEY

- User signs up
- User logs in
- User sees their unique forwarding email
- User forwards invoice emails
- System creates invoice entries
- User reviews extracted invoice details
- User edits if needed
- User tracks unpaid, paid, overdue invoices
- User manages vendors
- User marks invoices as paid

3. REQUIRED PAGES / SCREENS

A. Auth
- Login page
- Signup page
- Forgot password page (optional simple version)

B. Onboarding / First-use
- Welcome card
- Show unique forwarding email
- Copy-to-clipboard action
- Step-by-step instructions:
  1. Forward invoice email
  2. Wait for processing
  3. Review in dashboard

C. Dashboard
- Top stats cards:
  - Total invoices
  - Unpaid amount
  - Overdue amount
  - Paid this month
- Recent invoices table
- Needs review section
- Quick actions:
  - Add vendor
  - Add invoice manually
  - Copy forwarding email

D. Vendors Page
- Vendors table
- Search
- Status filter (active/inactive)
- Add vendor button
- Edit vendor action
- Vendor detail drawer/modal
- Show related invoices count and outstanding amount

E. Invoices Page
- Table with columns:
  - Invoice number
  - Vendor
  - Invoice date
  - Due date
  - Total amount
  - Status
  - Source
  - Duplicate flag
  - Actions
- Filters:
  - Search
  - Status
  - Source
  - Vendor
  - Date range
- Bulk actions optional only if easy

F. Invoice Detail / Review
- PDF preview section
- Extracted fields form
- Editable fields:
  - Vendor
  - Invoice number
  - Invoice date
  - Due date
  - Currency
  - Subtotal
  - Tax total
  - Total amount
  - CGST
  - SGST
  - IGST
  - Status
  - Payment reference
- Metadata:
  - source
  - source message id
  - created at
- Duplicate review UI if duplicate_status is suspected
- Buttons:
  - Save changes
  - Mark as paid
  - Mark as unpaid
  - Confirm duplicate
  - Ignore duplicate

4. IMPORTANT COMPONENTS

- App shell layout

- Stats card
- Reusable data table
- Filter bar
- Search input
- Form fields
- Select dropdowns
- Status badge
- Empty state component
- Error alert
- Loading skeleton
- Copy email card
- PDF/file preview card
- Duplicate warning card

5. VISUAL STYLE

- Clean B2B SaaS look
- Minimal colors
- Strong readability
- Table-first design
- Clear status badges:
  - unpaid = yellow/orange
  - paid = green
  - overdue = red
  - needs_review = blue or purple
- Focus on density and clarity, not marketing visuals

6. UX PRIORITIES

Highest priority:
- Fast invoice review
- Easy table scanning
- Clear status visibility
- Smooth forms
- Obvious onboarding

Medium priority:
- Good empty states
- Helpful validation messages
- Responsive layout

Low priority:
- Animations
- Complex charts
- Micro-interactions
