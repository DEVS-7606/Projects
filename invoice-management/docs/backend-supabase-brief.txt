BACKEND / SUPABASE BRIEF
PROJECT: Invoice Management MVP
GOAL: Design and create backend schema and logic for v1 only

1. ARCHITECTURE

Use Supabase for:
- Authentication
- Postgres database
- Row Level Security
- Storage for invoice files

Use a server/API layer for:
- Email webhook ingestion
- OCR processing
- Duplicate detection
- Invoice creation pipeline

2. AUTH MODEL

Use Supabase Auth for login.
Do not extend auth.users directly.
Use a separate public.profiles table linked to auth.users.

3. TABLES REQUIRED

A. profiles
Columns:
- id uuid primary key references auth.users(id)
- email text
- username text unique not null
- business_name text null
- phone_e164 text null
- timezone text null
- onboarding_status text null
- created_at timestamptz default now()
- updated_at timestamptz default now()

B. vendors
Columns:
- id uuid primary key default gen_random_uuid()
- user_id uuid not null references public.profiles(id) on delete cascade
- name text not null
- gstin text null
- email text null
- phone text null
- address text null
- default_payment_terms_days integer null
- notes text null
- aliases text[] null
- is_active boolean not null default true
- created_at timestamptz not null default now()
- updated_at timestamptz not null default now()

Constraints:
- default_payment_terms_days is null or >= 0

Indexes:
- index user_id
- index gstin
- unique index on (user_id, lower(name))

C. invoices
Columns:
- id uuid primary key default gen_random_uuid()
- user_id uuid not null references public.profiles(id) on delete cascade
- vendor_id uuid null references public.vendors(id) on delete set null
- invoice_number text not null
- invoice_date date null
- due_date date null
- currency text not null default 'INR'
- subtotal numeric(12,2) null
- tax_total numeric(12,2) null
- total_amount numeric(12,2) not null
- cgst_amount numeric(12,2) null
- sgst_amount numeric(12,2) null
- igst_amount numeric(12,2) null
- status text not null default 'unpaid'
- paid_at timestamptz null
- payment_reference text null
- source text not null default 'email'
- source_message_id text null
- file_url text null
- raw_ocr_text text null
- extracted_fields jsonb not null default '{}'::jsonb
- duplicate_status text not null default 'none'
- duplicate_of_invoice_id uuid null references public.invoices(id) on delete set null
- created_at timestamptz not null default now()
- updated_at timestamptz not null default now()

Constraints:
- status in ('unpaid', 'paid', 'overdue', 'needs_review')
- source in ('email', 'whatsapp', 'upload', 'manual')
- duplicate_status in ('none', 'suspected', 'confirmed', 'ignored')
- subtotal is null or subtotal >= 0
- tax_total is null or tax_total >= 0
- total_amount >= 0
- cgst_amount is null or cgst_amount >= 0
- sgst_amount is null or sgst_amount >= 0
- igst_amount is null or igst_amount >= 0

Indexes:
- index user_id
- index vendor_id
- index status
- index due_date
- composite index on (user_id, status)
- composite index on (user_id, due_date)
- composite index on (user_id, vendor_id)
- composite index on (user_id, invoice_number)

4. RLS REQUIREMENTS

Enable RLS on:
- profiles
- vendors
- invoices

Policies:
- authenticated user can select only rows where id/user_id matches auth.uid()
- authenticated user can insert only rows belonging to auth.uid()
- authenticated user can update only rows belonging to auth.uid()
- authenticated user can delete only rows belonging to auth.uid()

5. STORAGE REQUIREMENTS

Create storage bucket for invoice files.
Bucket use:
- PDF invoices
- Image invoices

Storage rules:
- User can only access their own files
- Store files under path pattern like:
  user_id/invoices/file-name.pdf

6. EMAIL INGESTION FLOW

Goal:
Forwarded invoice email should become an invoice record.

Flow:
1. User forwards email to unique routing email:
   invoices+username@yourapp.com
2. Email webhook receives message
3. Parse recipient to identify username
4. Find matching profile
5. Extract attachment
6. Upload file to storage
7. Run OCR
8. Create or link vendor
9. Create invoice row
10. If extraction confidence is low, set status = needs_review
11. Run duplicate check
12. Save duplicate_status and duplicate_of_invoice_id if needed

7. VENDOR MATCHING RULES

Try to match vendor in this order:
1. GSTIN exact match
2. Name exact match within same user
3. Name fuzzy match or alias match
4. If not found, create new vendor with minimal info

8. DUPLICATE DETECTION RULES

Check duplicate candidates in this order:
1. Same user_id + same vendor_id + same invoice_number
2. Same user_id + same vendor_id + same total_amount + same invoice_date
3. Same user_id + same invoice_number + same total_amount

If a likely duplicate exists:
- Do not reject insertion
- Set duplicate_status = suspected
- Set duplicate_of_invoice_id to original invoice id
